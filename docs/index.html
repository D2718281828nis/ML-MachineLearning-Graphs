How graph neural networks work, and how to check that the graph helped

Every demo below runs live in your browser: watch messages flow through a GCN and a GATv2, remove the edges and see the network collapse to an MLP, measure the edge contribution ΔG, and see why a “when” answer can be defended without a graph while a “where” answer cannot.

1A graph is a hypothesis about who influences whom

A graph neural network gets two inputs: node features and edges. The edges are an assumption. The rest of this page is about how they enter the computation and how to test whether they earned their place.

A graph $G=(V,E)$ with $n$ nodes is stored as

  • a feature matrix $X\in\mathbb R^{n\times d}$: row $x_i$ describes node $i$ from its own measurements (an EEG channel, an engine sensor, a stock);
  • an adjacency matrix $A\in\{0,1\}^{n\times n}$: $A_{ij}=1$ if $i$ and $j$ are connected.

An MLP uses only $X$: it treats rows as independent samples. A GNN also uses $A$: each node collects messages from its neighbours, so its prediction can depend on information it does not hold itself.

This is useful only if the edges carry information about the target. If they don't, the GNN just has extra inputs it has to learn to ignore. That is the reason for the edge check further down.

2Message passing, step by step

Each layer does the same three things for every node at once: (1) every neighbour sends its current vector, (2) the node takes a weighted sum, (3) it applies a weight matrix and a nonlinearity. Only the weights in step 2 differ between GCN and GAT.

$$h_i^{(l+1)}=\sigma\Big(\sum_{j\in\mathcal N(i)\cup\{i\}} c_{ij}\,W^{(l)}h_j^{(l)}\Big),\qquad c_{ij}=\begin{cases}\dfrac{1}{\sqrt{\tilde d_i\tilde d_j}} & \text{GCN (fixed by the graph)}\\[6pt] \alpha_{ij} & \text{GAT (computed from features)}\\[4pt] \mathbb 1[i=j] & \text{edges removed}\end{cases}$$
negative valuepositive valueblue strokes into the selected node: weight $c_{ij}$ of each incoming message

Click a node to select it. Here every node has a single number as its feature, $W=1.5$ and $\sigma=\tanh$, so you can follow the arithmetic by hand. Real layers use vectors and learned matrices.

Twins A and B: same own feature, different neighbours

With edges, A (positive neighbours) and B (negative neighbours) drift apart. Press Remove edges: they stay identical at every layer, whatever the weights. This is local indistinguishability.

3GCN: averaging with fixed, degree-normalised weights

$$H^{(l+1)}=\sigma\big(\hat A\,H^{(l)}W^{(l)}\big),\qquad \hat A=\tilde D^{-1/2}\tilde A\,\tilde D^{-1/2},\quad \tilde A=A+I,\quad \tilde d_i=\textstyle\sum_j\tilde A_{ij}.$$
  1. Self-loop $A+I$: the node keeps its own vector in the sum; without it a node would forget itself.
  2. Symmetric normalisation $1/\sqrt{\tilde d_i\tilde d_j}$: a hub does not blow up, and a message from a hub counts less, because the hub talks to everyone.
  3. Shared weights $W^{(l)}$: one matrix for all nodes, as in a convolution over pixels.
  4. $L$ layers = $L$ hops. Two layers mix 2-hop neighbourhoods. Stacking many layers is repeated smoothing ($\hat A^{K}X$) and eventually makes all nodes look alike (over-smoothing).
Read the matrix in the playground. In GCN mode the matrix panel shows $\hat A$. It is computed from the graph alone and stays the same at every layer and for every input. The network can scale messages through $W$, but it can't choose which neighbour to listen to.

The repository's healthcare lab uses exactly this layer (GCNConv in healthcare-gnn-lab/src/healthcare_gnn/models/gnn.py): two graph layers and a linear head, with kind="gat" switching to attention.

GCN: Kipf & Welling, ICLR 2017.

4GAT / GATv2: the network learns whom to listen to

$$e_{ij}=a^{\top}\,\mathrm{LeakyReLU}\big(W[h_i\,\|\,h_j]\big),\qquad \alpha_{ij}=\frac{\exp e_{ij}}{\sum_{k\in\mathcal N(i)\cup\{i\}}\exp e_{ik}},\qquad h_i'=\sigma\Big(\sum_{j}\alpha_{ij}\,W h_j\Big).$$
  • The weights $\alpha_{ij}$ depend on the features of both ends, so they change from input to input and from layer to layer.
  • Each row of $\alpha$ is a probability distribution over the neighbourhood (it sums to 1).
  • GATv2 applies the nonlinearity before the dot product with $a$. In the original GAT it came after, which made the ranking of neighbours the same for every query node (“static attention”).

Switch the playground to GATv2 and change a neighbour's feature with the slider: the strokes and the matrix rows change, while in GCN they don't. The demo uses fixed parameters that favour neighbours similar to the receiving node. A trained model would learn $W$ and $a$.

Attention as an explanation for “where”. It is tempting to read $\alpha_{ij}$ as “node $i$’s decision came from neighbour $j$” and to rank a source node this way. That reading assumes the edges carry information. If the network does just as well with no neighbours ($\Delta_G\approx0$), the weights only describe how the network spread its attention, not where an event came from.

GAT: Veličković et al., ICLR 2018. GATv2: Brody, Alon & Yahav, ICLR 2022.

5What network is left when the edges are removed

It is the same GCN or GATv2 with one change: the graph builder returns ∅. Every layer then becomes an ordinary fully connected layer applied to each node separately.

GCN with $A=0$

$$\tilde A=0+I=I,\quad \tilde D=I\ \Longrightarrow\ H^{(l+1)}=\sigma\big(H^{(l)}W^{(l)}\big)$$
$$h_i^{(l+1)}=\sigma\big(W^{(l)\top}h_i^{(l)}\big)\qquad\text{(only the node's own state; no messages)}$$

Two layers:

$$\hat y_i=\operatorname{softmax}\big(W_2\,\sigma(W_1x_i)\big)$$

This is a multilayer perceptron applied to every row $x_i$, with the weight matrices shared by all nodes.

GATv2 with $A=0$

$$\mathcal N(i)=\{i\}\ \Rightarrow\ \alpha_{ii}=\frac{e^{e_{ii}}}{e^{e_{ii}}}=1\ \Rightarrow\ h_i'=\sigma(Wh_i)$$

The attention vector $a$ still exists but has no effect: a softmax over one element is always 1.

Why ΔG is measured against “GNN, A = ∅” and not against an MLP

$$\Delta_G=\mathrm{score}\big(f_\theta(X,A)\big)-\mathrm{score}\big(f_\theta(X,\varnothing)\big)\quad\text{same }\theta\text{-init, folds, seeds}$$

GNN with label-derived edges vs MLPalso: the label leaks through the edgesno, and inflated

Example from the text: on the brain data the MLP scores 0.868 and the network without edges 0.858. These are different models, so their gap says nothing about edges. In [@8CSXTP6C] a graph network scored 97 % against 83 % for an MLP. That gap mixes two effects: the architectures differ, and the label enters the edge weights.

6Lab: does the graph help? Measure ΔG live

The “GNN” here is a simplified graph convolution (SGC): $K$ rounds of $\hat A$ smoothing, then a small MLP head. The control is the identical pipeline with $A=\varnothing$. A third, independent MLP has its own hyper-parameters. Five stratified folds and fixed seeds are used, and everything is trained in your browser.

F1 against hops K (━ GNN · ╌ A = ∅ · ┈ component size, no labels)

What to try. Communities: ΔG > 0 on every fold, because edges are homophilous and smoothing removes feature noise. Random edges: same features, same edge count, but ΔG ≈ 0 or negative. Chains: the class depends on chain length, which no local feature can see. Smoothing over K hops picks up only the chain ends and climbs slowly (statement 4 in theory/graph-connectivity: the full signal needs about 19 hops). Sweep K, and compare with the label-free component size at k = 2, which separates the classes perfectly (1.00 against 0.18 for the best local method). Then set k = 3: the chains merge and the component score collapses.

When a graph wins (rule from the chains case)

$$\text{(a)}\ h(A)\approx1,\qquad\text{(b)}\ \Pr\big(y_i=1\mid B_r(x_i)\big)\approx p,\qquad \Pr\big(y_i=1\mid\mathcal K(i)\big)\in\{0,1\}$$

(a) the edges are homophilous; (b) the class is invisible in any small neighbourhood but fixed by a non-local structure such as the connected component $\mathcal K(i)$. Edges must also be built from features only: $A=A(x_1,\dots,x_n)$, never from $y$ or a proxy of $y$.

7The task: “when” is defended without a graph, “where” needs ΔG

The edge check does not compute the moment or the source. It decides which part of the answer may rely on the graph. The demo shows both parts on a simulated sensor network (brain, engine or market; the logic is the same).

“When”: estimated moment $\hat t$

  • The alarm comes from an extreme-value threshold fitted on each node's own background: peaks over a high quantile $u$, exponential (GPD, $\xi=0$) tail, threshold at exceedance probability $q$. No graph is involved.
  • $\hat t=\min_i t_i^{\text{alarm}}$. Nothing in it depends on a graph hypothesis, so one implementation transfers unchanged between systems whose graphs are physically different.
  • From the text: on benchmark R4 the alarm fires at sample 949 or 959 against a true onset at 932, in all four specification variants. The “when” answer is stable.
$$\Pr\big(x>u+z\mid x>u\big)\approx e^{-z/\sigma}\ \Rightarrow\ \text{thr}_i=u_i+\sigma_i\ln\frac{\hat\zeta_{u,i}}{q}$$

“Where”: source distribution $P(\hat s=v)$

  • The source is ranked through the graph: in the dissertation through attention weights $\alpha_{ij}$. Here a transparent stand-in plays that role: it scores each candidate $v$ by how well the alarm times fit graph distances, $t_i\approx\tau+\delta\,d_G(v,i)$.
  • That ranking only means something if the edges carry information. The edge check acts as a filter: with no confirmed contribution, the source answer is auxiliary and is not put forward as a result.
  • From the text: 0 of 28 checks confirmed an edge contribution, and on R4 the source is right only 2 times out of 4 and is sensitive to the detector specification. In the chains example the opposite holds: the class is a property of the component, and the graph wins 1.00 against 0.18.

In short. The check separates two cases. Either the answer comes from the node's own signal (“when”), which is defended because it doesn't depend on the graph. Or it would come from the edges (“where”), which is allowed only when the edge contribution is confirmed (the dissertation's rule (а)–(в)). With wrong edges the graph-based “where” looks just as confident in a single event, but over many events it does no better than the control.

8Hyperbolic graphs: room for trees

In a tree with branching $b$ the number of nodes at depth $d$ grows like $b^{d}$, but a Euclidean circle's length grows only linearly in its radius. Hyperbolic space grows exponentially, so trees and hierarchies embed with little distortion.

Euclidean disk

Poincaré disk: drag to pan, click a node

The Poincaré ball

$$\mathbb B^n_c=\{x:\ c\|x\|^2<1\},\qquad d_{\mathbb B}(x,y)=\operatorname{arcosh}\!\Big(1+\frac{2\|x-y\|^2}{(1-\|x\|^2)(1-\|y\|^2)}\Big)\ \ (c=1)$$
  • Distances blow up near the boundary. Equal-looking gaps near the rim are huge, which is where the leaves live.
  • Shortest paths (geodesics) are arcs orthogonal to the boundary, drawn as the tree edges on the right disk.
  • Dragging applies a Möbius translation $z\mapsto\frac{z+a}{1+\bar a z}$, an isometry: the picture changes, but all hyperbolic distances stay the same. Any node can be brought to the centre.
Raise the depth to 5 or 6. The Euclidean disk crushes the leaves together (closest leaves ≪ 1 edge length) and the leaf-distance distortion explodes. With the same disk size, the Poincaré embedding keeps leaves several times farther apart and cuts the distortion several-fold. Leaves sit near the rim, so drag the disk to bring any branch to the centre.

A hyperbolic GCN layer: lift, aggregate in the tangent space, map back

ball: drag the blue neighbours

tangent space at the origin

neighbours $x_j$ / $\log_0 x_j$$\exp_0\big(\tfrac1n\sum\log_0x_j\big)$naive Euclidean average

$$\exp_0^c(v)=\tanh\!\big(\sqrt c\,\|v\|\big)\frac{v}{\sqrt c\,\|v\|},\qquad \log_0^c(x)=\operatorname{artanh}\!\big(\sqrt c\,\|x\|\big)\frac{x}{\sqrt c\,\|x\|}$$
$$h_i'=\exp_0^c\Big(\sigma\big(\textstyle\sum_j \hat A_{ij}\,W\log_0^c(h_j)\big)\Big)$$

Vector addition and matrix products are not defined inside the ball, so the layer moves to the tangent space (an ordinary $\mathbb R^n$), runs a normal GCN step there and maps back. This is what HyperbolicGCN in the repository does (expmap0 → GCNConv on logmap0 → expmap0), with a learned curvature $c$ (softplus).

The same edge check applies. Hyperbolic geometry helps if the data is tree-like. Whether the edges help is still measured by ΔG against the identical model with A = ∅. In the repository's overlay data a hyperbolic GCN does no better than a plain k-NN classifier, because only 33 % of a red node's edges lead to red.

HGCN: Chami et al., NeurIPS 2019. HNN: Ganea, Bécigneul & Hofmann, NeurIPS 2018. Poincaré embeddings: Nickel & Kiela, NeurIPS 2017.
